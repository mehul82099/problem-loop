# Python 3.14 migration: a trailing dot changes pathlib stems and rename results

Date: 2026-11-04. This is an intentional compatibility change, not a newly discovered Python defect.

## Research

[CPython issue #140490](https://github.com/python/cpython/issues/140490) reported that the Python 3.14 single-dot suffix change also changed `PurePath.stem`, without an accompanying note in that attribute's documentation. The issue is now closed. [The documentation correction](https://github.com/python/cpython/issues/144450) merged in February 2026. Do not treat the old missing-note report as an unresolved runtime bug.

The original behavior change was deliberate: [CPython PR #118952](https://github.com/python/cpython/pull/118952), merged in May 2024, made a single trailing dot a valid extension. The [3.14 reference](https://docs.python.org/3.14/library/pathlib.html) documents this for suffix-related operations. The [3.13 reference](https://docs.python.org/3.13/library/pathlib.html) provides the earlier contract.

## Discussion

A filename-renaming script may use `stem` as a stable identifier, or assume that `with_suffix("")` leaves a filename ending in a dot unchanged. Those assumptions no longer hold across the 3.13/3.14 boundary. This is about string-level path semantics. It is not evidence that any particular filesystem accepts or preserves a trailing-dot filename.

The related [Ruff PTH210 rule](https://docs.astral.sh/ruff/rules/invalid-pathlib-with-suffix/) is Python-target-aware: a literal `with_suffix(".")` is invalid before 3.14, but valid from 3.14. [Ruff PR #19331](https://github.com/astral-sh/ruff/pull/19331) made that adjustment in July 2025. A clean lint run is not a migration audit: the rule checks invalid suffix arguments, not all changes in computed stems or rename destinations. Its documentation also acknowledges binding-inference false negatives.

## Conclusion

For applications accepting trailing-dot names, add explicit cases to the supported Python-version test matrix before upgrading. Do not blindly strip punctuation to make tests pass: decide whether a final dot is part of the application's identifier or an extension separator. If an application rejects those names, validate that policy explicitly rather than depending on a Python-version-specific `stem` result.

## Action: measured compatibility probe

Executed this read-only probe on Linux x86_64 using CPython **3.13.17** and **3.14.9**. Both completed successfully, checking six values per interpreter (12 value comparisons total). These are the versions actually run, not a claim about the earliest affected patch release.

For `p = PurePosixPath("report.")`:

| Expression | 3.13.17 observed | 3.14.9 observed |
|---|---|---|
| `p.stem` | `"report."` | `"report"` |
| `p.suffix` | `""` | `"."` |
| `p.suffixes` | `[]` | `["."]` |
| `str(p.with_suffix(""))` | `"report."` | `"report"` |
| `str(p.with_stem("renamed"))` | `"renamed"` | `"renamed."` |
| `str(PurePosixPath("report.txt").with_suffix("."))` | `ValueError` | `"report."` |

Save the following as `probe.py` and run it with each interpreter. It creates, renames and deletes no files. The version-based expected values cover this specific migration boundary; they are not a permanent guarantee for all future Python versions.

```python
import json, platform
from pathlib import PurePosixPath
p = PurePosixPath('report.')
try:
    dot = str(PurePosixPath('report.txt').with_suffix('.'))
except ValueError:
    dot = 'ValueError'
actual = dict(stem=p.stem, suffix=p.suffix, suffixes=p.suffixes,
              remove_suffix=str(p.with_suffix('')), replace_stem=str(p.with_stem('renamed')),
              dot_suffix=dot)
new = tuple(map(int, platform.python_version_tuple()[:2])) >= (3,14)
expected = (dict(stem='report', suffix='.', suffixes=['.'], remove_suffix='report',
                 replace_stem='renamed.', dot_suffix='report.') if new else
            dict(stem='report.', suffix='', suffixes=[], remove_suffix='report.',
                 replace_stem='renamed', dot_suffix='ValueError'))
assert actual == expected, (actual, expected)
print(json.dumps({'python':platform.python_version(), 'observed':actual, 'checks':6}, sort_keys=True))
```

## Publisher checks and limits

- This finding and probe are original additions under the repository's MIT license. Linked upstream work remains its authors' work.
- No filesystem mutation, Windows runtime test, Ruff execution, application integration test, or performance benchmark was performed.
- `PurePosixPath` intentionally isolates path-string behavior from operating-system I/O. Do not generalize the table to `PureWindowsPath` or Windows filename handling without testing them separately.
- Sources establish an intentional change and a resolved documentation gap. They do not establish data loss in an application. Review code that derives keys or rename targets from these operations; the application-level impact depends on its inputs and policy.
