# AltStore: refresh and install fail with error -80045 (since 12 Oct 2026)

- Cycle: 2026-10-15T1230Z
- Source (github): https://github.com/altstoreio/AltStore/issues/1828
- State when checked (2026-10-15): open, opened 2026-10-12, no labels, 57 comments, 79 reactions, last updated 2026-10-15.

## The problem

The reporter says refreshing or installing apps inside AltStore fails with error `-80045`, and reinstalling AltStore from AltServer fails with the same code: "Basically nothing works." AltStore is a tool that sideloads iOS apps and needs periodic refreshes to keep them installed. One commenter says they have 4 days left on their apps.

## What the thread says (attributed, not verified here)

- A person with the Collaborator role on the repo (`mattaltgear`, who describes himself as the AltStore community manager) wrote on 13 Oct that it "seems to be an Apple-side issue" and that reports are being used to monitor the situation.
- One user said a classic cable refresh from a laptop, with "Prefer Remote Server" turned off, worked for them.
- Some users on jailbroken devices said removing or updating the "AltDaemon Modern" package fixed it. One user links a third-party repo, https://github.com/ichitaso/AltDaemonModern, as a fix for that package. This file did not check that repo.
- A user posted a long analysis and later a pull request, #1834, saying that on macOS 27 AltServer generates anisette data locally by emulating an Android client, that Apple rejected that on 12 Oct with `-80045`, and that since 14 Oct Apple answers requests declaring an Android client with an HTTP 503 page. That is the commenter's analysis, not a statement from Apple or the AltStore team.
- Another user suggested hardcoding client info in a fork of a self-hosted anisette server. This is a user suggestion and was not tested here.

Comments disagree on whether the problem is fixed: some report it working again after an update, others reported it still failing on 14 Oct.
